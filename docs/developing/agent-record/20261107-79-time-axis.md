## What was done

### The time axis module

`ui/time_axis.rs` holds what Playback, the Charts tab and the Series view share.

- `RunTime` holds a `TimeUnit` and the run's tick length as an `f32`, and `RunTime::at(tick)` is `TimeScale::time_at`, the decimal product S2 wrote for the `time` column.
  A sample's x on a plot therefore equals the `time` column a stats export writes for its tick.
- `plot_x(tick, time)` returns the tick, or its time when `time` is set.
- `axis_label(unit)` returns "Tick", or the unit's file name with a capital letter ("Day", "Week").
- `counter_text(tick, time)` returns "Tick 24", or "Tick 24 (12 days)", in the final `SPEC.md`'s form.
  The unit is singular at exactly one unit ("Tick 2 (1 day)" for a half-day tick), and the time prints as Rust prints an `f64`, so 12 days reads "12" and half a day "0.5".

`AppState::loaded_time` returns the `RunTime` of the loaded run: the loaded entry's time scale and the tick length among `loaded_values`, through `TimeScale::tick_length_in`.
It returns `None` with no model loaded or for a model with no time scale.

### Playback

`playback_ui` draws the tick counter after Play and Step on their row, from `tick_counter(app)`: the snapshot's tick and `loaded_time`.
Before the loaded model's first snapshot the row shows no counter.
The explanation for a model with no time ("a tick is one step of time") is left to S13a, which shows it in sheet mode only, as the plan says.

### The Charts tab

`stats_chart` keeps its early returns and its vector and histogram plots, and draws the time series through `stats_plot(ui, history, time)`.

- The x axis label is `axis_label` of the run's unit.
- Each sample sits at `plot_x` of its tick (`stat_points`).
- `Plot::include_y(0.0)` keeps 0 in the y range, and egui_plot labels it on the left axis (F22, D87).
- A series holding one sample, as at tick 0, draws as `Points` of radius 3 in the stat's colour (D107), and any longer series as the `Line` it was.

The legend and the Unlimited history checkbox stay as they were, which D73 maps to the page's legend and its whole-run plot.

### The Results tab's Series view

`ResultsStore` keeps the model's `TimeScale` (`time`), from the entry in `for_sweep` and `from_result_set`, and again in `model_changed` for an entry of the store's model id.
A folder whose model this device lacks has none, and draws in ticks.

- `ResultsStore::time_unit` returns the unit, or `None` when the value columns hold no tick length, as in a folder written before the model declared a time scale.
- `ResultsStore::config_time(config_id)` reads the config's tick length from the value column named by the time scale, as `runs.csv` writes it, and returns a `RunTime`.

`SeriesView::cached_plot` replaces each band's ticks by their times for a config with a time scale, and `run_lines` places each run's points at `plot_x` of the config's tick length.
Replicates of one config share one tick length, so a band pools samples of one time.
`SeriesPlot` holds the `time_unit` it was computed with, the x axis label reads it, and a change of unit drops the cache.

### Hidden parameters

- `params_ui` skips a hidden parameter and shows "This model has no parameters." when every parameter is hidden.
- The graph editor's world panel lists only the shown parameters and counts them in its "Parameters (N)" header.
  `param_with` already kept the flag on an edit since S2's review.
- The Sweep tab keeps a row per parameter from `schema.params`, so nothing changed there.
  A test holds it.
