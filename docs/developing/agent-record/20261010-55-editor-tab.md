# Editor tab

> Milestone M6 of #49 (dynamic model loading), the first testable aim of its plan: a grid rule edited and run in the official app, on native and in a browser.
> The Editor tab is the plan's temporary test harness, which #37's node editor replaces.
> It holds one model file as text in a `TextEdit` with no wrapping and no highlighting, in one scroll area beside a gutter numbered from the galley's rows, over a list of the last Apply's outcome.
> Apply reads the text through `ModelFile`, compiles the rule, hands a one-entry set to `AppState::install_models` and selects the model, so a run of the rule past tick 0 waits on M5's Rebuild model dialog, again after a Cancel, and a run at tick 0 restarts at once.
> A refused text leaves the set and the run alone, and each problem is a selectable label reading `<line>:<column> <message>` whose press moves the cursor there.
> A fault of a run built from the applied code, before the run passes tick 0, goes to the Editor as the edit's outcome in place of the fault dialog, which catches the device's late report in a browser.
> A lost device, a failed poll and a device out of memory stay with the dialog.
> New grid rule loads the Life starter, Edit model loads a runtime model's canonical text, and Open model and Save model go through the existing file dialogs, in a new File menu as well.
> On native the egui MCP server drove New grid rule, an edit to birth on 3, 6 and 8, Apply, the Rebuild model dialog, Rebuild, a loop and a syntax error at their lines, and the old run stepping on.
> In Chrome on WebGPU the same flow gave the same counts as native, tick for tick.
> Two reviews found nine problems, all fixed: the wait message and Apply's tooltip, the dialog after a Cancel, the faults the Editor claimed, the Editor opening beside a hidden Viewport, the sideways scroll bar below the view, and three slips in the guide and a doc comment.

### The tab (`ui/dock.rs`)

- `Tab::Editor` is the last variant, since `egui::Id::new(tab)` hashes the discriminant and egui keys each tab's stored scroll state on it.

### The Editor (`ui/editor/`)

**`mod.rs`** holds `EditorPanel`, a new `AppState::editor`: the text as typed, the file name, the `ApplyOutcome` of the last Apply, the open and save status, the `ModelSource` applied last (private), and a character to scroll to.
`editor_ui` draws three egui panels inside the tab:

- a header with New grid rule, Open model, Save model and Apply, named through `sweep::layout::add_button` for the accessibility tree, then the file name and status, and `NO_COMPUTE` in the theme's warn colour on an adapter without compute;
- a resizable bottom panel with the outcome's line, then one `Label` per `CodeDiagnostic`, selectable and in the theme's error colour, sensing clicks when it has a place, with its notes below;
- the code view.

A press collects an `EditorRequest`, applied once the tab has drawn, as the Sweep tab does.
`ApplyOutcome` is `Applied` ("Model applied."), `AwaitingRebuild` ("Model applied. Press Rebuild to run it from tick 0."), `Installed` ("Model applied. Press Build to run it."), `Unchanged` ("Model code unchanged."), `Refused` ("Model not applied. Fix the problems below.") or `Faulted` ("Model build failed. Fix the problem below."), the last two with their problems.
`settle_outcome` turns `AwaitingRebuild` or `Installed` into `Applied` once the loaded model runs the applied source, after Rebuild or Build, and `AwaitingRebuild` into `Installed` once the dialog closes without a rebuild.
Apply's tooltip reads "Check model and install it", and the hint before any Apply "Press Apply to check and install the model.".

**`code_view.rs`** draws one `TextEdit::multiline(..).code_editor()` in Henad Mono, through a layouter whose job never wraps (`LayoutJob::simple` at an infinite width, trailing spaces kept, rows at the text edit's line height).
The field sits in one `ScrollArea::both`, as wide as the longest line and at least as tall as the view, and the gutter sits outside it, to its left.
Both scroll bars stay at the edges of the view, and the gutter stays in place while a long line scrolls sideways.
`gutter_numbers` turns the galley's rows into line numbers: a row starts a line when it is the first or the row above ends in a line break, and a wrapped continuation gets none.
The numbers are painted right-aligned at each row's height as the scroll area placed it, clipped to the gutter, in the weak text colour, and in the error colour on a line with a problem.
`char_index_at` maps a diagnostic's line and character column to a character index, clamped to the line and the text, and `move_cursor` writes the `TextEditState` cursor and requests focus.
The scroll to the cursor runs inside the scroll area on the next frame, along both axes.

### Apply (`editor::apply`)

1. Without compute, Apply is disabled, and a call returns `NO_COMPUTE` as a refusal.
2. `ModelFile::parse(text)` then `entry()`.
   A failure sets `Refused` with the error's diagnostics, and nothing else changes.
3. When the loaded model already runs this source and the set holds it, the outcome is `Unchanged`.
4. Otherwise the editor records the source as applied, then `install_models` gets a one-entry set.
   M5's path then rebuilds a run of the same id at tick 0, or opens the Rebuild model modal for one past tick 0.
   `install_models` passes over an entry the set already holds, as after a Cancel, so Apply then calls `settle_loaded` (now `pub`) itself while the loaded run of that id differs from the source and no modal waits.
5. `select_model(id)`.
6. When the rule is not loaded, no modal waits and `run_at_start` holds (made `pub`), Apply builds through `reset_simulation`.
   A modal for the rule makes the outcome `AwaitingRebuild`, and a run of another model past tick 0 keeps going with the outcome `Installed`.

A fault that the Editor claimed during steps 4 to 6 ends Apply there, so a build that failed is not tried a second time.

### Faults of the applied code (`state.rs`)

`report_fault` and `load` both end in `show_fault`, which now takes the faulting `ModelEntry` in place of its name.
When the run has no snapshot past tick 0 and `EditorPanel::claims` the entry's source and the fault, the fault goes to `EditorPanel::show_fault` as `Faulted`, with the message the fault modal would show (`ui::fault::detail`, factored out of the modal), and the Editor comes to the front.
`claims` passes over `FaultKind::DeviceLost`, `FaultKind::Poll` and a device out of memory (`Fault::is_out_of_memory`), which no edit of the code fixes.
Any other fault opens the modal as before.
On native a device error at build time reaches `load` through `catching_on`.
In a browser `catching_on` pushes no scopes, and the device reports a refused pipeline through `GpuContext`'s uncaptured-error handler into the `FaultSink`, which `logic` reads a frame or more later.
Both reach the Editor while the run is still at tick 0.
`EditorPanel::load`, behind New grid rule, Open model and Edit model, forgets the applied source.
Edit model asks `EditorPanel::is_applied` whether the selected entry runs the applied source.

### Filling and saving the text

- **New grid rule**, in the Model panel, the Editor header and the File menu, loads `life_starter()`, the canonical text of `GridRule::life()` through `ModelFile::from_rule(..).to_toml()`, and brings the Editor to the front.
- **Edit model**, in the Model panel for a selected entry whose `ModelSource::code` is in `GridRule::CODE_FORMAT` (`editable_text`), loads that canonical text.
  It keeps the text, edits since included, when the selected entry's source is the one the Editor applied last.
- **Open model** goes through `OpenTarget::Model`, a single `.toml` file picked as "Model file" on native and in a browser.
  `receive_open` loads it as UTF-8 and applies nothing, and a file that is not UTF-8 leaves the text alone with "Open failed: <name> is not UTF-8 text".
- **Save model** goes through `SaveTarget::Model` and `AppState::save_as`, with the text as written, under the opened or saved file's name, then `<id>.toml`, then `model.toml`.
  A browser downloads it.
  `poll_saves` records the saved or downloaded name, and the status line reads it.
- The menu bar gains a **File** menu (`MDI_FILE_OUTLINE`) in front of View, with New grid rule, Open model and Save model, the last disabled with `EMPTY_EDITOR` while the text is empty.

## Issues found & future directions

- **A renderer's validation error at tick 0 of the applied code reaches the Editor.**
  A lost device, a failed poll and a device out of memory stay with the fault dialog, but the uncaptured-error handler takes every other device error, the renderer's included, and the Surface::configure error above would read as the rule's "Model build failed." if it struck before the first step.
  A paused run at tick 0 leaves the device idle, which makes that unlikely, and the message is still shown.
  Telling a pipeline error from a surface error would mean reading wgpu's message text, which differs per browser.
- **A surface reconfigure error offloads a running GPU model.**
  With the display asleep, "Failed to wait for GPU to come idle before reconfiguring the Surface" from egui-wgpu's own rendering reaches the `FaultSink` and ends a GPU run within seconds, compiled models included.
  It predates M6 and is egui-wgpu's surface handling meeting `GpuContext::new`'s handler, which takes every unscoped error as the simulation's.
- **Apply beside another model's run past tick 0 builds nothing.**
  The plan names the dialog for a run of the edited model.
  For another model's run the Editor reads "Model applied. Press Build to run it." and the run keeps going, as Build would end it without a dialog.
- **The text has no undo across New grid rule, Open model and Edit model.**
  Each replaces it without asking, and nothing is kept when the app closes, both as the plan's cuts leave them.
- **R makes builds asynchronous.**
  `editor::apply` reads the loaded entry right after `install_models` and `reset_simulation` to choose its outcome, and the tests assert the loaded source straight after Apply.
  M6 merges after R in round 4, and the merge needs `wait_for_build` in the tests and a settle of the outcome once R's build lands, which `settle_outcome` already does for `AwaitingRebuild` and `Installed`.
  A fault of R's background build has to reach `show_fault` with the entry for the Editor to claim it.
  Resolved when M6 was cherry-picked onto R: `PendingBuild` keeps the entry and `finish_build` passes it to `show_fault`, the tests call `wait_for_build`, and `settle_outcome` turns `Applied` into `Installed` once Cancel leaves nothing loaded.
  A fault of the build machinery, and a fault `report_fault` takes from a sink while a build runs, go to the modal through `show_fault_in_modal`.
- **`model-files` is now called.**
  M4's open question stands: every app on the template's `app` feature carries naga_oil once the Editor calls the composer, 0.50 MB gzipped on the web by M4's measure.
- **M7's model file reference page.**
  `docs/guide/editor.md` describes the file in brief, and should link M7's reference page once both are merged.
- **The gutter shows no column marks and the code no underline.**
