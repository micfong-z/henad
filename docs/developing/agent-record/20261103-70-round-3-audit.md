## What was done

### `vec.from_angle` on the device

`CaseValue::NearVec2F` compares a `vec2f` per component within a tolerance, as `Near` does for an `f32`.
`vec.from_angle` now has three `Both` cases within 1e-5: east at length 2, north at length 3, and south west at length 1.
`every_known_answer_of_both_scopes_holds_on_the_device` now also fails on any kind with a WGSL form allowed in a tick, action, view or stats pass whose own cases ran none on the device.
With the old host case put back, it fails naming `vec.from_angle` alone, so no other kind had the gap.
After the change 317 cases run on the device.
The library lock moved with the cases.

### Float sums on a grid

The grid engine reduced counts alone, so the compiler refused `stat.sum` and `stat.mean` in a grid graph, and two library 1 kinds worked over agents only.
They now reduce on the device.

- **henad-compute.** `GpuGridSpec::sums` names the float lanes the reduce shader sums, zero from `new`. Such a shader binds `partials` and writes the total of each cell workgroup at `partials[block * sums + lane]`. The engine folds them with `GpuLaneReduce::over_blocks`, a new constructor over a leaf of its own shape, after the counters' copy, and reads both back together. `GridHooks::stats_with_sums` (provided, default `stats`) receives each lane's total. A spec with no sums builds no tree, so the stock adapters and grid rules run as before. `demand` and `heap_bytes` count the partials.
- **henad-graph.** The grid reduce template declares `henad_sum_<k>` before the cell's bounds check, calls `block_sum(henad_local, ...)` after the counters, and writes each workgroup's total. `GridProgram::spec` sets `sums`, and `GraphHooks::stats_with_sums`, forwarded by `SharedHooks`, feeds the totals to `run::finish`. The reduce pass's workgroup bytes add the 1024 of `block_sum`'s scratch.
- **Tests.** `float_sums_of_a_grid_graph_reduce_on_the_device` (henad-models, `graph_grid_sums.rs`) builds a grid graph through `ModelFile::entry` at 1 by 1, 16 by 16, 100 by 37 and 300 by 211, and holds a sum and a mean of an `f32` lane and a sum of a `vec2f` to closed forms before and after a step, and to a replay. The lane holds quarters, so every order of addition sums exactly. A first run returned zeros: `SharedHooks` did not forward the new hook, which the test caught. The grid stats cases of `stat.sum` and `stat.mean` now run on the grid on the device as well as in an agents world, and a plant that added 1 to each partial failed them. `a_float_sum_on_a_grid_writes_partials` replaces the refusal test. `a_tree_over_blocks_sums_as_the_tree_over_the_population` holds `over_blocks` to `new` bit for bit.

### The count bound of `math.max` and `math.clamp`

`a_count_bound_follows_max_and_clamp` (henad-graph `checker.rs`) holds `math.max` to its larger side, to no bound with an unknown side, and `math.clamp` to its `hi` whatever its `x`, including `lo` past `hi`.
With both rules replaced by no bound, the test fails.
Writing it showed that `math.clamp`'s written semantics said `lo` wins when `lo > hi`. Its form `min(max(x, lo), hi)` and its own case "lo past hi" give `hi`. The semantics now say `hi`, and the lock line moved.

### The float Repeat gate over agents

### Decisions made on the maintainer's behalf

- **Grid float sums were built, not documented away.** Both kinds are in library 1 as general-purpose statistics, and a mean of a float lane is a common need of a grid model. The agents engine's tree and `block_sum` already existed, so the change is a constructor, a spec field, a provided hook and a reduce template branch. The stock grid adapters and grid rules run unchanged, since a spec with no sums builds no tree.
- **A provided hook instead of a new signature for `GridHooks::stats`.** It keeps every existing implementor as it was.
- **The budget test was left failing.** The audit marks it the maintainer's call. The corner test now shows what each choice means: accepting the refusal and changing the test keeps the schema equal to the stock models', a lower `max_count` must fall to about 195000 for `gpu_boids.toml` and breaks schema parity, and a calibrated walk rate would raise the charge, since record #68's one measurement put a visit at about four times its current charge.
- **The corner test was renamed.** Its old name described faults that the budget now prevents.
- **The wrap refuses rather than reshapes.** A refused wrap leaves the document as it was, as the other wrap refusals do.
- **A node moved out of a region moves.** Drawing a non-member differently inside a frame would leave it looking misplaced. Placing it outside keeps frames meaning membership.
- **The cost was measured at three rounds on the loaded machine.** It replaces figures from an older shader. The idle five-round run stays the maintainer's.
- **No new benchmark gate run for the grid engine.** The change adds an `Option` that is `None` for every stock model and touches neither the step path nor the encode of a model without sums. The G2 gate's commands in record #66, run against `f154309`, check it.
- **The `math.clamp` semantics were corrected** with the lock, since the form and the case already agreed on `hi`.

## Issues found & future directions

- **A non-member can still land inside a frame** when a frame grows over a node that is not in its region, such as a member dragged next to it. Only Move out of region moves a node. Arrange still spreads a region, as record #69 notes.
