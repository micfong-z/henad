# Fire counts

> S31 builds row X1 of round 1 on the engine channel of S8, as the maintainer's answer 9a asks and decision D48 sets out: fire counts on by default.
> The sheet lowering records, for each change line of the card that runs each tick, the Boolean output of the lowered graph that holds where the line applies, and `SheetFile::fire_lines` returns them as a `FireLines`: the `Probes` and the line each counts for.
> A Become counts through the `fired.<rule>` outputs of its property's `cat.transition`, one row per state for a Become from any state, so "otherwise" and competing lines count only the cells their row fired for, a Become from any state counting cells already in its state too.
> A Set, Steer, Keep between, Move by, Leave or Record counts through its condition, and a Set that a higher Set can override, a Move to and a change whose condition always holds show no count.
> `ModelFile::entry` and the Editor's preview compile a sheet with the probes of `model_file::sheet_probes`, the one place an empty list would turn counting off for every sheet.
> The Card pane shows each count in grey at the right of its line, described as "Line 2 applied to 2 cells in tick 4.", while the run is the sheet as it now lowers, and keeps it while the run is paused.
> A planted blinker counts 2 and 2 on the host and on the device, the forest fire's counts on the device equal the host's for 50 ticks, and the SIRD sheet's competing lines each count exactly the cells that took their state.

## What was done

### henad-graph

- **Recording fires in the lowering.** `Builder::record_fire(node, port, line)` keeps a temporary node, a port and a line id. `transition` records `fired.<rule>` for every row it writes, so a Become from any state records one output per state. `CardLowering::fires_when(id, condition)` records a condition that is the output of a node, and a constant `always` records nothing. A Set records its condition after `any_time` unless `overridden_set` finds a line of `CardRelations::otherwise_of` that the report does not skip. A line inside a Repeat records nothing. Steer, Keep between, Move by, Leave and Record record the result of `change_condition`. Move to records nothing.
- **Keeping the fires that count.** At `finish`, `Builder::fire_lines` keeps a fire whose node sits in a tick pass outside every region and is no `math.expr` or `fn.call`, renumbers it, and returns `Lowered::fires`. A button's lines, a condition worked out inside a Repeat and a node that normalisation copies drop out there.
- **`FireLines`** (`sheet/lower/table.rs`, re-exported from `sheet`): `probes`, `lines`, `is_empty` and `counts_by_line(counts)`, which adds a line's rows into a `BTreeMap` of line id to count and returns an empty table for counts of another length than the probes. `SheetFile::fire_lines` returns it.
- **`AgentProgram::compile_with_probes_and_fault_names`**, for a sheet of agents, which needs both.
- **Words.** `sentence::fire_count` ("30,877") and `sentence::fire_count_description` ("Line 2 applied to 2 cells in tick 4.", singular for 1).

The probes recorded per sheet, in recording order:

| Sheet | Lines counted |
| --- | --- |
| Game of Life | l2, l3 |
| SIR epidemic, chance SIR | l2, l3 |
| Majority vote | l2 (rows A and B), l3 (rows A and B) |
| Forest fire | l2, l3, l4, l5 |
| SIRD | l2, l3, l4 |
| Ant foraging | l3, l4 (Leave), l11 (Set), l14, l15 (When conditions), l10 and l13 (Becomes from any state, two rows each) |
| Random walk, boids, bounded confidence, mobile SIR | none: every change always applies or is a Steer by a strength |

### henad-explore

- `model_file::sheet_probes(file)` returns `file.fire_lines().probes()`.
- `graph_entry` takes an optional private `SheetAdditions` (the fault names and the probes) in place of the fault names alone. A grid sheet compiles through `GridProgram::compile_with_probes`, and a sheet of agents through `AgentProgram::compile_with_probes_and_fault_names`. A graph file compiles as before.

### henad-app

- `GraphProgram::compile_with_probes`, and `SheetEditor::program` compiles the preview with `sheet_probes(file)`, the probes Apply builds with.
- `sheet::LineFires` (the counts' tick and the count of each line) and `sheet::line_fires(sheet, loaded, snapshot)`, computed once a frame by `editor_ui` through `sheet_fires`. It is `None` unless the loaded entry's code equals the sheet file's code, the snapshot's counts hold a tick past 0, and the counts map onto the sheet's probes. An edit therefore takes the counts away until the preview built from the edit counts a tick, and a paused run keeps its snapshot and so its counts.
- `SheetShown::fires`, `card_pane(..., fires)`, `CardsShown` (the report, the values and the counts) and `CardDrawing::fires`, set only on a card that runs each tick.
- `line_ui` narrows each row of such a card by `COUNT_WIDTH` (72 points), and `fire_count_ui` draws the line's count in grey, right-aligned in that column level with the row's top, in a child `Ui` that takes no space from the column, with the description as hover text and as the label's AccessKit description.

### Review

A reviewer with a fresh context found three faults and four nits, all fixed in `fix: s31 review findings [draft]`.

- **A change inside a Repeat could count.** `fires_when` recorded the fire before the Repeat check, and `Builder::fire_lines` dropped a fire only for a node inside a region. A Steer or Move by with a blank condition inside a Repeat inside a When takes the When's condition, a node outside the region, and kept its probe, against the guide and the `FireLines` doc. `fires_when` now records nothing for a line with a `repeat_of`, Leave and Record included, and `a_change_inside_a_repeat_has_no_count` holds it (it failed before the fix with `["l2"]`).
- **The rows reflowed when counts came and went.** `line_ui` narrowed the rows only while the snapshot held counts, so every line of the tick card reflowed on Play and twice after each edit to a playing preview. `SheetEditor::refresh` now keeps the ids of the counted lines in `SheetEditor::counted` (kept over an edit that stops the sheet lowering), and `CardDrawing::counted` reserves the column on a tick card with such a line whether or not counts have arrived. The Game of Life and SIR app test checks line 3's bounds before Play against those with counts, and `an_edit_hides_the_counts_and_a_blank_keeps_the_column` checks line 3's size over an edit in place and a blank. Both fail with the old rule.
- **The sheet's code was written every frame.** `line_fires` called `SheetFile::code`, which writes and hashes the lowered graph's whole semantic text, on every frame the Editor showed a sheet. `refresh` now keeps the code in `SheetEditor::code`, once per edit, and `line_fires` checks the snapshot's counts (a tick past 0 and one count per probe) and the loaded entry before it compares that code.
- **Nits.** `overridden_set` now reads `CardRelations::otherwise_of` in place of a second copy of the rule. The guide lists every change other than a Become that always applies, says a Become from any state also counts the cells already in its state, and reads "disappear after a change". The summaries of `CardsShown`, `SheetAdditions` and `FireLines` name their subjects. The record's summary and deviation are corrected here, and the row for `fire_count_description` in gate section 10.21 was added at the merge.

The live UI check was not repeated after the fix: the lock was taken and the app launched on G15F1, but the screen was locked overnight, so the window never painted and the egui server timed out. ## Deviations

- **Words the final `SPEC.md` lacks.** The final `SPEC.md` leaves fire counts out, and the gate's wording table has no row for them. The card shows the number alone, as round 1 section 2 draws it ("░ 30,877"), grouped as the cost messages group digits, and its hover text and AccessKit description read "Line 2 applied to 2 cells in tick 4.". "applies" is the word the card's "otherwise (when line 2 does not apply)" already uses. The row belongs in the wording table's section 10.21 at the next gate.
- **Counts on change lines only.** The plan allowed counts on yes or no lines "if the final `SPEC.md` shows counts there". It shows none anywhere, and round 1 speaks of the lines that fire, so only change lines count.
- **A Set counts through its condition, and an overridable Set has no count.** The plan names "its select" for a Set. The select chain's outputs are values, and no Boolean output of the lowered graph holds "this Set applied" when a higher Set of the property can also apply, since that needs the condition and the negation of each higher one. A probe cannot add a node, so a Set that reads "otherwise" shows no count, and every other Set counts where its condition holds, which is where it applies. The same reasoning leaves out a Move to, whose open test decides.
- **Counts on the other agent changes.** The plan names Become and Set alone. Steer, Keep between, Move by, Leave and Record count through their condition too, since S28 put those lines on the card and their conditions are outputs of the graph. A change whose condition always holds, a Become apart, has no count, and neither has any change inside a Repeat, which may run the line several times in a tick or not at all. Boids, random walk and bounded confidence therefore show none.
- **Topic files.** The plan names `agents/henad-graph-sheet.md` for the probes and `agents/henad-app-sheet.md` for the card. The first was 39,342 characters, so the paragraph went into `agents/henad-graph-sheet-lower.md`, with one clause in the first. The card is described in `agents/henad-app-card.md` since S22 split it out.
- **The app preview compiles with the probes too.** D48 says `ModelFile::entry` sets the range in one place. The Editor's preview compiles the lowered graph itself, so the one place is `model_file::sheet_probes`, which both call.
- **No record commit.** The record is this draft outside the repository, numbered and committed at the merge, so the branch holds the feature commit and the review fix alone.

## Issues found & future directions

- **The counting cost at 10M cells is still unmeasured**, and counts are now on for every sheet, in the app, the CLI and sweeps. The commands below measure it. If it is high, `sheet_probes` returning empty probes turns counting off for every sheet without touching the editor.
- **A sweep counts and reads nothing.** Each command buffer of a sheet's sweep counts its last step, as S8 noted. A switch on the sweep's build could drop the probes there if the measurement asks for it.
- **The count is of the last step of a batch.** With adaptive batching the app runs hundreds of steps per batch, and the count is of the batch's last step, the tick the hover text names. At one tick per snapshot it is every tick.
- **An overridable Set shows no count.** Counting it needs a probe that is a condition and the negation of others, which `Probes` cannot express. A probe of a conjunction, or a node the lowering writes for the purpose (which would change the code identity), would fill the gap.
- **A change that always applies shows no count**, though its count is the number of cells or agents. The card could show the population there, at the cost of a number on every boids line.
- **`agents/henad-graph-sheet.md` is at 39,403 characters.** The next milestone that adds to it splits it.
