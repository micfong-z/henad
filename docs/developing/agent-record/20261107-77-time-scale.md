## What was done

### Hidden parameters

`ParamDescriptor` holds a private `hidden: bool`, set by the builder `hidden()` and read by `is_hidden()`, beside `on_reload()` and `percent()`.
The flag is display only: `--set`, `--vary` and a spec file reach a hidden parameter as any other.
`schema_hash` reads parameter ids, kinds, bounds, defaults and options, so it already left the flag out, and its doc now says so.
`a_hidden_parameter_hashes_like_a_shown_one` holds the schema hash and a plan's hash equal with and without the flag.

### The time scale in henad-core and henad-compute

`metadata::TimeScale` (`#[non_exhaustive]`, `new`, public fields `unit` and `tick_length`) names the unit of one tick and the id of the parameter holding its length.

- `tick_length_index(params)` and `tick_length_in(params, values)` find the parameter and a run's value by id, `None` for a missing id or a value that is not an `f32`.
- `TimeScale::time_at(tick, tick_length)` returns the time at a tick.
  It multiplies the tick by the decimal digits the `f32` displays with and divides by the power of ten once, so a tick length of 0.1 puts tick 3 at 0.3 instead of 0.30000000447034836.
  Past 2^53, or for digits that do not fit, it falls back to the binary product.

`ModelMetadata.time` (`None` from `new`, set by `ModelMetadata::time`) carries it, and so does `EntryDeclarations.time`, `None` from `new` and in every `register_*`.
`ModelEntry::from_declarations` moves the declarations' time scale into the metadata, and `ModelEntry::metadata` exposes it.
The facade re-exports `TimeScale` at its root beside `TimeUnit`, and `facade_paths.rs` names it.

### The two `[[param]]` keys in henad-graph

`ParamTable` reads `hidden` and `tick_unit`.

- `ParamTable::into_graph_param` returns the descriptor, hidden when the table sets `hidden = true`, and the unit `tick_unit` names through `TimeUnit::parse`.
  An unknown unit is refused with the list of units, a plural such as `days` among them.
- `ParamTable::into_descriptor`, the grid rule's reader in henad-explore, refuses either key at the table: "parameter 'x' must not set `hidden`, which only a graph file reads".
- `GraphDocument.time` holds the one `TimeScale` a table's `tick_unit` names.
  The reader refuses a second `tick_unit` at its table, naming both parameters.
- `write_param` writes `hidden = true` only for a hidden parameter, and the graph writer adds `tick_unit` after the tick length's other keys.
  A file setting neither key writes the text it wrote before.
- `check_tick_length` refuses a tick length that is not an `f32`, is not hidden, or has a `min` of 0 or below, and a time scale naming no declared parameter.
- `RenameParam` renames the time scale's parameter, `renamed_param` keeps the flag, and `RemoveParam` drops the time scale with its tick length.
- `GridProgram` and `AgentProgram` copy `document.time` into their parts and set `EntryDeclarations.time`, so a manifest's replayed text and an expert copy keep their time axis.

The three rates fixtures in henad-models set `hidden = true` and `tick_unit = "day"` on `tick_length`, and their comment and the procedure document say so.

### Schema and `--params`

- `param_json` writes `"hidden": true` only for a hidden parameter, and `schema_json` writes `"time": { "unit": "day", "tick_length": "tick_length" }` only for a model with a time scale.
  No example model has either, so the golden `--params --json` files hold.
- `params_text` writes the bare word ` hidden` after `apply` and `format` for a hidden parameter alone, which `scripts/bench_matrix.py`'s `key=value` parse skips.

### The `time` column

- `StatsWriter::tick_length(length)` adds a `time` column after `tick`, `TimeScale::time_at` of each sample's tick.
  `export_stats` in henad-cli gives the writer the setup's tick length for a model with a time scale.
- `SeriesWriter::new` and `appending` take the tick length's position in a config's values, which adds the `time` column, and `write_run` takes the run's parameter values to read each run's own tick length.
  `OutputDir::open_writer`, `append_writer` and the crate's `memory_writer` take the model's `Option<&TimeScale>`, and the sweep, the search and the pumped sweep pass `entry.metadata().time`.
  `header_line(columns, timed)` is the header a resume and a search resume compare, so a resume of a timed folder writes the same header.
- `check_series_header` reads a header one column wider than the ids and the stats, with `time` third, as timed, and `parse_series_row` checks the time as a number and skips it.
  A stat labelled `time` in a header without the column still reads, since the width tells the two apart.
- `crates/henad-explore/tests/fixtures/series-be338ec/` is a sweep of SIR written by a build of `f4088d7`, with the procedure that recorded it in its `README.md`.

### Deviations from the plan
