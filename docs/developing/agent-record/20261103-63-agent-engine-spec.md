# GPU agent engine from a spec

> Milestone A1 of #37, in round 1 of `dev-docs/37-gpu-node-models/plan.md`.
> `GpuAgentSpec` holds a GPU agent model's declarations as values, its functions sit behind `AgentHooks`, and the non-generic `GpuAgentEngine` builds every wgpu object from it.
> `GpuAgentState<M>` reads a spec from `M` and forwards every call, in the orientation stock shaders assume.
> Each pass binds through a `SideTable`, which lets a later milestone commit a writer's output to the passes after it.
> The specs and hooks of both engines are public behind `runtime-wgsl`.
> `Structure::GpuGrid` and `Structure::GpuAgents` hold `Cow`s, a breaking change for 0.4.
> The stock `gpu_ants` steps byte for byte as it did before the change, and the interleaved benchmark gate waits for an idle machine.

## State before

`37-node-editor` at `e816b44`.
The GPU grid engine already built from a `pub(crate)` `GpuGridSpec` (record #52).
`GpuAgentState<M>` was generic over its model and read the consts at every use, and `BufferSpec`, `PassSpec` and `BindingDecl` hold `&'static` strings, which a model composed at run time cannot fill without leaking.
Every step pass bound with one orientation, reads on the current side and writes on the next, and every action bound in place.

## What was done

### The spec (`gpu/agent_spec.rs`, new)

`GpuAgentSpec` follows lowering §7.3 and the plan's "Structure" and "Per-pass commit" decisions.
It holds the id, `AgentBufferSpec`s, the position and colour buffer indices, the index flag, the counter count, `AgentPassSpec`s, an optional `AgentDisplaySpec`, an `AgentReduceSpec`, `AgentActionSpec`s, the stat series and `Box<dyn AgentHooks>`.
`AgentHooks` holds `dims`, `buffer_lens`, `seed_buffers`, `index_cell_size`, `pass_params_bytes` and `stats`, each the counterpart of the `GpuAgentModel` function of that name.
`GpuAgentSpec::from_model` reads a spec from a model type, borrowing its strings.

`SideTable` holds one `SideRow` per buffer, each naming the `BufferSide` (`Current` or `Next`) that a read-only and a writable binding resolve to.
`SideTable::swapping` is the single orientation of a step, display and reduce pass, and `SideTable::in_place` that of an action.
A buffer with one side resolves both values to that side.
The tables are read once, when the bind groups are built, and the step path never sees them.
Every double buffered buffer swaps once at the end of a step, whatever the tables say.

`GpuAgentSpec::assert_contracts` holds the labels and workgroup checks the engine made before, in the same order and with the same messages.
It adds five refusals: a table of another length, a position or colour index past the buffers, one side of a buffer bound both read-only and writable in one pass, a position or colour buffer that is not drawable, and a double buffered buffer that no step pass writes to its next side.
The last three reach hand-written models, as the review section below describes.

### Owned binding names (`gpu/shader_spec.rs`, new)

`BindingDecl.name` is `&'static str`, generated by henad-build and written by hand-written models, and the plan keeps those forms.
`ShaderBinding` is the same declaration with a `Cow` name, and `ShaderSpec` holds a source and a list of them.
The grid spec's `GridShaderSpec` became this shared `ShaderSpec`, which has its two callers now.
`binding::named_buffer_target` in henad-core is `buffer_target` for a name built at run time, and `buffer_target` forwards to it.
A stock pass allocates one `Vec` of bindings per spec, once per build or per `demand` call off the step path, and each name stays borrowed.

### The engine and the adapter (`gpu/agent_engine.rs`)

`GpuAgentEngine` is the old generic state with `M::` replaced by the spec, and `PassBuilder` takes the spec and a table for each pass.
`encode_steps`, `encode_stats_passes` and the snapshot passes are unchanged apart from where they sit.
`encode_action` reads a cached invocation count, and calls `pass_params_bytes` once per press as before.
`GpuAgentState<M>` keeps every public function, its `Debug` output and its docs, and forwards each.
The engine stays `pub(crate)`, as `GpuGridEngine` does.

### Public behind `runtime-wgsl`

The plan's "Public constructors" decision covers both engines.
`gpu/mod.rs` re-exports these only with the feature on, from `pub(crate)` modules.
Each struct and enum is `#[non_exhaustive]` and each struct has a `new`, with two exceptions: `SideTable` has a private field and no attribute, and `BufferSide` is an enum and has no `new`.
`AgentHooks` and `GridHooks` are traits, and a new hook takes a default body:

- `GpuAgentSpec`, `AgentHooks`, `AgentBufferSpec`, `AgentPassSpec`, `AgentDisplaySpec`, `AgentReduceSpec`, `AgentActionSpec`, `SideTable`, `SideRow`, `BufferSide`;
- `GpuGridSpec`, `GridHooks`, `GridActionSpec`;
- `ShaderSpec`, `ShaderBinding`;
- `entry::EntryDeclarations`, now in `entry/declarations.rs`;
- `ModelEntry::from_gpu_grid_spec` and `ModelEntry::from_gpu_agent_spec`.

`GpuGridSpec.buffers` became `Vec<Cow<'static, str>>`, the one gap lowering §7.3 names for grids.
The generalised grid spec with dual and plain sets stays with G2.

`GpuSimState` gains a provided `read_buffer`, `None` by default, which the agent engine and adapter implement.
A parity test holding only an entry's built state needs it, the adapter test here reads the lanes through it, and A2's oracle will too.

### `Structure`

`Structure::GpuGrid.buffers` is `Cow<'static, [Cow<'static, str>]>`.
`Structure::GpuAgents.buffers` and `passes` are `Cow`s of the new `GpuBufferInfo` and `GpuPassInfo` in henad-core, the description both kinds of model fill, and the facade's root exports them.
`GpuAgentSpec::structure` and `GpuGridSpec::structure` fill the variant from a spec, and `GpuAgentSpec::topology_hint` the hint.
`crates/henad-app/src/ui/model.rs` follows with two `as_ref` calls, and no other reader changes.

### Calls on the hot paths

A step and a snapshot call no hook, a press calls `pass_params_bytes` once, and a stats read calls `stats` once.
`a_step_calls_no_hook` counts each hook's calls across a step, a batched run past one submission and an encoded snapshot.
`GpuAgentState<M>::encode_steps` now crosses a non-generic function, once per batch of up to 64 steps.

### What the review found

A review of the milestone reported five findings, each fixed here.
The two checks below came from code reading, and neither failure was reproduced on a device.

- **A double buffered buffer that nothing writes (medium).**
  `GpuAgentEngine::new` seeds only side `a`, and `encode_steps` flips the sides every step, so a buffer no step pass writes alternates between the seed and zeros.
  `GpuAgentSpec::new` defaults to empty `steps` and reaches this directly, and `lowering.md` §5 refuses it only in the graph checker.
  `assert_contracts` now requires, for each double buffered buffer, a writable binding in a step pass whose row writes `Next`.
  A row that writes `Current` has the same hole, so a writable binding alone does not pass.
  An action does not count, because it binds in place.
  Every hand-written model in the workspace meets this: `gpu_boids` writes `pos_out`, `vel_out` and `color_out` in `step.wgsl`, and `gpu_ants`, the tutorial's `GpuForagingModel` and `StatlessGpuBoids` either declare no second side or copy boids' buffers.
- **A non-drawable position or colour buffer (low).**
  The engine built it without `VERTEX` usage and the view passed it to `set_vertex_buffer`, which faults at the first draw after a successful build.
  `assert_contracts` now refuses it.
  This changes behaviour for a hand-written model that only runs headless with such a buffer, which built before and now panics. The CHANGELOG marks it as breaking.
- **`assert_no_conflict` undocumented on the adapter (low).**
  At `e816b44` an in-place `pos_in` and `pos_out` built, and only the press failed.
  From `from_model` on, the build panics even if the action is never pressed.
  Only models that were already broken are affected, so the check stays, with the panic in the `# Panics` of `new_seeded` and a CHANGELOG clause.
  The old and new builds were not run side by side.
- **The public types' stability attributes (low).**
  `BufferSide` and `SideRow` lacked `#[non_exhaustive]`, and `SideRow` had no `new`, against the plan and `docs/developing/releasing.md`. Both have them now.
  The list above also claimed more than was true for the traits, for `SideTable` and for `BufferSide`, and now says what each one does.
- **`ShaderSpec`'s `Debug` (low).**
  It left out the source and ended in `.finish()`. It now ends in `.finish_non_exhaustive()`, as `PassSpec` and `GpuGridSpec` do.

Each refusal has a test in `gpu/agent_spec.rs`, which failed before its assert was added.
`the_agent_engine_refuses_a_second_side_no_step_pass_writes` and `the_agent_engine_refuses_positions_it_cannot_draw` in `henad-models/src/tests/gpu_contracts.rs` hold the same refusals on the hand-written path, through `GpuAgentState<M>`.
`an_action_that_reads_and_writes_one_side_is_refused` pins the check that was already there.

### Benchmark gate, for an idle machine

The gate is a median paired ratio, new time over old time, of at most 1.05 on `gpu_boids` and `gpu_ants`.
Close other work and let the machine cool first.
Check that at least 12 GB is free, since the old tree builds its own `target`.

```bash
# Once, from the root of a checkout holding this change: an old tree at the base commit and both release binaries.
NEW_TREE=$(git rev-parse --show-toplevel)
BENCH=$(mktemp -d)
git worktree add "$BENCH/old" e816b44
(cd "$BENCH/old" && cargo build --release -p henad-cli)
(cd "$NEW_TREE" && cargo build --release -p henad-cli)
OLD=$BENCH/old/target/release/henad-cli
NEW=$NEW_TREE/target/release/henad-cli

# Interleaved, flat-out GPU steps. 4096 agents make the encode's CPU cost show, and the larger runs the dispatch.
for round in 1 2 3 4 5; do
  for model in gpu_boids gpu_ants; do
    for agents in 4096 100000 1000000; do
      $OLD $model --steps 2000 --reps 5 --set num_agents=$agents --json > "$BENCH/old-$model-$agents-$round.jsonl"
      $NEW $model --steps 2000 --reps 5 --set num_agents=$agents --json > "$BENCH/new-$model-$agents-$round.jsonl"
    done
  done
done

# The median paired ratio per model and size, each round's median new time over its median old time.
python3 - "$BENCH" <<'PY'
import json, statistics, sys
bench = sys.argv[1]
def median_elapsed(path):
    lines = (json.loads(line) for line in open(path))
    return statistics.median(line["elapsed_s"] for line in lines if line["kind"] == "rep")
for model in ("gpu_boids", "gpu_ants"):
    for agents in (4096, 100000, 1000000):
        ratios = [
            median_elapsed(f"{bench}/new-{model}-{agents}-{r}.jsonl") / median_elapsed(f"{bench}/old-{model}-{agents}-{r}.jsonl")
            for r in range(1, 6)
        ]
        print(model, agents, f"{statistics.median(ratios):.3f}", [f"{ratio:.3f}" for ratio in ratios])
PY

# A blocking stats sample on every tick. gpu_ants replays exactly, and its CSVs are expected to match byte for byte.
```

## Issues found & future directions

- **A flaky test that predates this change.**
  `a_location_survives_a_panic_on_a_rayon_worker` in `henad-compute/src/fault.rs` fails often enough to stop `./check.sh`, and `a_site_recorded_on_the_thread_for_another_panic_is_not_taken` fails with it when the fault tests run alone.
  The fault tests alone failed 145 of 200 runs at `e816b44` and 156 of 200 here, and the whole library 7 of 20 at `e816b44` and 10 of 20 here.
  The two tests share rayon's global pool, and the second probably leaves a panic site or takes one from the first, which was not investigated further.
  The file is unchanged, and the test was left as it is. It needs its own fix before `./check.sh` can be relied on.
- **`replays_exactly` is not in the spec.**
  Lowering §7.3 lists it, and neither engine reads it, the conclusion record #52 reached for grids.
  `EntryDeclarations` carries it.
- **Declarations and a spec can disagree.**
  An entry's stats and actions come from `EntryDeclarations`, and the engine's from the spec.
  A public constructor documents that the two list the same items, and checks nothing, as `from_grid_spec` did.
  A compiler builds both from one source, so A2 can derive them in one place.
- **`GridActionSpec` and the grid spec's sets.**
  The grid spec has no side table, and every buffer ping-pongs.
  G2 splits the dual and plain sets, and `SideTable` is in the agent spec module until then. G2 can move it to `shader_spec.rs` if its passes use it.
- **The grid engine's `read_buffer`.**
  It returns `None`, since the engine drops its buffers after binding them. G2 needs to keep them if its oracle reads lanes through a built state.
- **The facade.**
  The specs stay out of `henad::*`. The plan has henad-graph above henad-compute, and it takes them directly.
- **`from_model` per call.**
  `GpuAgentState::demand`, `geometry_for` and `max_storage_bindings` build a whole spec each call, as `GpuGridState` does. They allocate a few small vectors, and none is on a step path. A registered entry shares one spec.
- **Commit.**
  The maintainer allowed local commits for the rounds. This work is in two unsigned drafts on `37-a1`, `feat: agent engine spec [draft]` and `fix: a1 review findings [draft]`, for the maintainer to reword and sign.
