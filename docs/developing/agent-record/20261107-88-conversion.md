# Conversion

> S23 builds the library half of answer 8b: `henad_graph::sheet::convert` copies the graph a sheet lowers to into a graph file of its own, under the sheet's id with `_expert` added and its name with " (expert)" added, numbered when taken.
> The copy has its own code, since its id, name and description enter the semantic text, and its `[editor] origin` record names the sheet's code, the copy's code at conversion, the sheet's file and the hash of its canonical text.
> Every node sits in one frame: the nodes of one line, the nodes several lines share with `lines = [...]`, or the nodes of a part of the sheet, each frame titled with the line's number and sentence or the part's words.
> Named results and reads of a property take labels, the purpose and each parameter's meaning become notes, and no node is placed.
> The converted Game of Life checks clean and runs tick for tick like the sheet for 200 ticks at seed 7 with three presses, on the host and on the device.
> `changes_since_conversion` compares the copy with the graph the sheet lowers to and lists the copy's nodes added, removed and changed by id under their frames, Make function and Copy keep frame membership, and `SetVariantColor` sets a variant's colour.

## What was done

### The conversion

`crates/henad-graph/src/sheet/convert.rs` is new and private, and `sheet` re-exports `convert`, `ConvertOptions`, `ConvertRefusal` and `ConvertError`.

- `convert(&SheetFile, &ConvertOptions)` clones the lowered document and sets the header's and the target's id and name from the options, and both descriptions to "Converted from the author model Game of Life. Edit it as a node graph." (`sentence::converted_description`).
  Every node keeps its id and key, so the copy draws what the sheet draws.
- `ConvertOptions { id, name, file, date }` has public fields, and `ConvertOptions::new(&SheetDocument, date, taken)` finds the first copy whose id and name `taken` reports free: `game_of_life_expert` and "Game of Life (expert)", then `game_of_life_expert_2` and "Game of Life (expert 2)" (`sentence::expert_copy_number_name`), up to 999 tries.
  `file` defaults to the sheet's id with `.toml` added.
  The library reads no clock and knows no installed model, so the date and `taken` come from the app.
- `ConvertRefusal::of(&SheetReport)` returns `Errors` before `SkippedLines` (D19), and `tooltip()` returns the wording table's "Fix the problems on the card to convert." or "Some lines do not run yet. Finish or delete them to convert."
  `convert` checks again and returns `ConvertError::Refused(SkippedLines)` for a sheet with a skipped line.
- The `[editor]` region of the copy:
  - `origin`, a `ModelOrigin` with `kind = "sheet"`, `model`, `name`, `file`, `hash` (FNV-1a 64 of `SheetFile::to_toml`), `code` (the sheet's code hash), `copy_code` (the copy's) and `converted`, each 16 lowercase hex digits where it is a hash.
  - `node.<id>.label` and never `pos` (D68): the result node of each named line takes its name ("Alive neighbours"), and each read of one of my properties takes "my Status", a neighbour's "their Status".
  - One `[[editor.frame]]` per origin group, pass by pass in stack order.
    A node a line owns is that line's.
    A sheet node at `card.<card>.<property>`, the transition or select chain's write, belongs to the Become and Set lines of that property on that card that run.
    The shared `stat.count_by` belongs to the count measures of its property, a start's nodes to the start, and a measure's, button step's or colour rule's nodes to that part.
    The shared read of a property takes the group its readers share: the union of their lines, or their one part of the sheet.
    A group of one line merges with that line's frame, so Clear's read, transition and write sit in "Clear line 1: Become Dead from any state, always".
    Single lines come first in display order, then shared groups, then parts of the sheet, coloured blue, purple and gray.
    `line` holds one origin and `lines` several (D29): a line id such as `l2`, or a sheet part path such as `measure.alive`.
  - `[[editor.note]]` for the purpose, titled "Purpose", and for each parameter's meaning, titled with the parameter's name (D24).

### Changes since conversion

`crates/henad-graph/src/sheet/changes.rs` is new and private, and `sheet` re-exports `changes_since_conversion`, `ChangeGroup` and `ChangesError`.
It refuses a copy with no origin record, and a sheet whose canonical text no longer hashes to `origin.hash` with "Game of Life has changed since this conversion." (`sentence::original_changed`).
It diffs the copy's nodes against the sheet's lowered graph by node id across passes and functions.
A node is listed under the first frame of its canvas that holds it in the copy, or else in a fresh conversion, so a removed node lists under the frame it sat in at conversion, and a node in neither under its canvas with no title.

### Frames that follow edits (C3)

`MakeFunction` calls `EditorRegion::move_frame_members`: each frame of the canvas holding a moved node keeps its other members and takes the call, and a copy of it on `function.<id>`, every key kept, holds the moved nodes.
`GraphBuilder::copy` writes each frame of the canvas that holds a copied node, cut to the copied nodes, and `Paste` adds a frame of its own on the target canvas for each, around the pasted ids.

A variant's colour is part of the semantic text, so the code changes.

### Deviations from the plan

- **`ConvertOptions` holds `file`.**
  The plan lists `{ id, name, date }`, and the origin record needs the sheet's file name, which only the app knows.
  `ConvertOptions::new` fills it with the sheet's id and `.toml`, and the app can set another.
- **The error refusal comes from `ConvertRefusal::of`.**
  `convert` takes a `SheetFile`, as the plan says, and a sheet with an error has no `SheetFile`.
  `ConvertRefusal::of` takes the checker's report, which the app holds for any sheet, and `convert` itself can only meet a skipped line.
- **The topic file.**
  The plan puts the conversion in `agents/henad-graph-sheet.md`, which stood at 39,120 characters.
  The conversion's paragraphs would pass 40k, and the plan's split moves the lowering out, about 17k characters that S21, open beside S23, edits for rates.
  The conversion went to `agents/henad-graph-sheet-convert.md` instead, with a pointer, and the lowering stays where S21 expects it.
- **The HighLife edit.**
  `expert.md` section 3.4 rewires the shared Become (`n16`), which the diff lists under "Lines 2 and 3".
  The plan's acceptance names one changed node under the frame of line 2, so the test changes line 2's comparison into an or of two new comparisons, and the two new nodes list as added in no frame.
- **Sheet frames carry `line`.**
  The plan describes `line` and `lines` for nodes lines made.
  A frame of a part of the sheet carries the part's path in the same keys, as `expert.md`'s converted Game of Life does (`cells.status.starts_as`, `measure.alive`, `button.clear`), so Show changes and the problem list can name every frame's origin.
- **Shorter sheet frame titles.**
  `expert.md` titles the start "Sheet, Status starts as: Alive with chance Initial density, otherwise Dead (Randomise runs it again)".
  No sentence of a start exists in `sheet::sentence`, so the title reads "Sheet, Status starts as".
- **Paste adds a frame of its own.**
  C3 asks Copy to carry membership.
  A paste puts the pasted copies in a new frame with the same title and origins instead of the original frame, so the original frame stays drawn around the nodes it held at conversion.
  D22 marks nodes added after conversion by no frame, and a paste of a line's nodes into a frame of that line is the one exception, since those nodes did come from that line.
- **`LineMap::result_node`.**
  The plan names labels for named results without saying how to find a result's node.
  The lowering already knew it, and the table now records it.
- **Device size.**
  `expert.md` ran the copy at 1024 by 1024.
  The device test runs 128 by 128 and the host test 64 by 64, enough for Clear to empty the world and Randomise to refill it, and short enough to read every tick's lane back.
- **Notes carry `title`.**
  The region's existing notes have `scope`, `pos` and `text`.
  A sheet note has no canvas, so it has no `scope` or `pos`, and its `title` says what it is about.

### Review

A reviewer listed two should-fix findings and three nits, and `fix: s23 review findings [draft]` holds every one of them.

- **Agent paths in the grouping and the titles.** The grouping, the labels and the titles assumed a grid sheet: they matched `cells.` alone, looked property names up in the cells alone, and kept only Become and Set lines as writers.
  S17's lowering writes `agents.<property>` reads and starts, `card.<card>` for the shared look and `card.<card>.<heading>` for a Move's heading, which would have taken gray frames titled with the raw path.

  A sheet node with no part of its own (the read of a property, `card.<card>`, and a change no line writes) now resolves from its links in rounds: its readers' shared group once every reader has one, else its resolved feeders' shared group for the end of a chain no node reads, else a frame of its own.
  Sheet titles cover every path the two lowerings write: the card heading for `card.<card>`, the new value for a change, "colour each bird by Heading" for a colour by heading, and `SHEET_PART_WORDS` instead of the raw path for anything else.

  `every_sheet_starter_converts_and_checks_clean` now asserts that every frame origin is a line id or a part path, and that no title holds a raw path, an empty sentence or the fallback words.

   The review fix added `EditorRegion::node_pos`, and the app's `place_unplaced` already arranges such a copy on load.
   S27 still has to call the conversion and open its copy.
2. Ungroup does not carry frames back.
   The call sits in the frame after Make function, and Ungroup's copies take fresh ids and join no frame.
   An expert who makes a function and ungroups it loses the frames of those nodes.
3. `changes_since_conversion` compares nodes only.
   A `SetVariantColor`, a parameter edit or a renamed lane changes the copy's code and lists nothing.
4. The grouping rule meets only grid sheets so far.
   Boids' Steer chain and the ants' fused fold share nodes across lines in ways the grid sheets do not.
   `every_sheet_starter_converts_and_checks_clean` reads `starters()`, so it runs over the agent starters once S17 and S20 add them, and S21's SIR with rates.
   The review fix made the grouping general for agent paths, and a trial merge with S17 showed the agent starters converting with readable frames (see Review).
   The merge check made the two items the rebase onto S17 required, listed under Review.
5. Frame titles can be long, and C4 (a frame at least as wide as its title, or a clipped title with the full text on hover) is the app's, in S27.
6. A frame title quotes the line as the card printed it at conversion and never changes (D25), and a line reordered later on the sheet keeps its old number in the copy.
7. Runs of the boids on the device are not repeatable at one seed, for the sheet and for round 1's hand-lowered file alike.
   The polarisation band now has no lower edge above 0, and a test that compares two runs of one agent model on the device needs a band wide enough for that spread, or a cause found in the engine.
8. A radius fold that several looks at agents share takes the label of one of them, the last line recorded.
   A copy of boids shows one name on the shared fold, and S27's display names may want the lines' names together.
