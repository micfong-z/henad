## What was done

### The canonical form

`ir-spec.md` section 10 asks that two spellings of one document write one text.
The writer now normalises the two cases the audit found.

- **Count lists.** `ConfigType::CountList` is a set. `normal_config` writes it ascending with each count once, as it writes a `U64Text` value as lowercase hexadecimal. The writer normalises and the checker keeps accepting any order, since a list in another order reads the same and refusing it would only add an error for the user to fix. `grid.life_like`'s semantics now say the lists are sets, which moves its lock line.
- **Links.** `normal_link` writes a link bare when it names the only output of a node outside every region around the reader. A region read from its own body keeps the port, since there a bare link names nothing and the port names an inner output. `normal_stat_source` does the same for `[[stat]] from`.

A canonical text now holds bare links, and a bare link to a `stat.count_by` of a one-variant category stops naming one output once a variant is added.
`AddVariant` and `RemoveVariant` therefore first name the variant on such links (`name_bare_counter_links`).
Without this, adding a variant broke the link, and removing the only variant missed the stat's reference.

Tests:
- `respellings_of_the_life_starter_write_one_text` applies the audit's four edits and a fifth, `[3, 2, 2, 3]`, to the starter, and holds each to the starter's semantic text and hash, with no checker error.
- `a_link_keeps_its_port_where_a_bare_link_would_mean_another` holds that a body's read of its region (`n3.k`) and a stat of a counter with two outputs keep their ports, and that a stat of `stat.count_where` writes bare.
- `a_bare_link_to_a_counter_of_one_variant_is_named_before_a_variant_edit` adds a variant to a one-variant category read through a bare stat link, and checks the result. Removing the only variant is refused as referenced.

The audit's probe, rerun against the change, reports one hash for each of its respellings and a moved hash for its two controls.

### Float to integer conversions

WGSL converts a float to an integer by clamping to the float values the target holds, then truncating.
naga 30 emits that as a clamp before the cast, and an Apple M4 Pro returned these values for a hand-written shader on wgpu 30:

| Expression | Result |
|---|---|
| `u32(5e9)` | 4294967040 |
| `u32(4294967040.0)` | 4294967040 |
| `i32(3e9)` | 2147483520 |
| `i32(-3e9)` | -2147483648 |
| `i32(2147483520.0)` | 2147483520 |
| `u32(-1.0)` | 0 |

The definitions now state that rule, and the host form follows it, so the cases keep scope Both and G2 can run them on the GPU.
`conv.to_u32` from an `f32` clamps to 0 through 4294967040 (`0x4f7fffff`), and from an `f64`, a host-only input, to 0 through `u32::MAX`, which an `f64` holds.
`conv.to_i32` from an `f32` clamps to `i32::MIN` through 2147483520 (`0x4effffff`).
A NaN still gives 0 on the host, and the host's clamp leaves a NaN as it is before the cast, since `f32::min` would turn it into the top.
The cases are "clamps above to the largest f32 below 2^32", a new "the largest f32 below 2^32 is exact", a host case "f64 clamps above to u32::MAX", and "clamps above to the largest f32 below 2^31".
Both lock lines moved.

`rng.threshold` also casts a float, `(p * u32::MAX as f32) as u32`, and saturates to `u32::MAX` at `p = 1`.
Its definition computes it on the host when the model is built, so it never runs in a shader and keeps the stock form.

### The flaky fault test

`fault.rs` keeps a process-wide list of recent panic sites for a panic that rayon re-raises on another thread, read by message.
The list was a FIFO of 16 entries.
The two rayon tests each raise up to 32 identical panics on the pool, so when they ran together one burst pushed the other's site out before its catch read it.
Run alone, the `fault::` tests failed 44 of 150 times.

The list now keeps each `(message, site)` once and moves it to the newest place when it is recorded again, so a burst of one panic holds one entry.
A catch reads the site without removing it, so two catches of one panic both find it, and the cap is 64 distinct sites.
The newest site with a message is never older than the panic being caught, so a site left listed does not mislead a later catch.
After the change the `fault::` tests passed 300 of 300 runs.
`a_burst_of_one_panic_keeps_the_sites_of_others` raises a panic on one thread, a burst of 100 on another, and re-raises the first. It fails on the old code and passes now.
The same fallback serves the app, where a parallel kernel failing one assert on every worker is the common case, so CHANGELOG lists it under Fixed.

## Issues found & future directions

- **Other ways a bare link loses its meaning.** A link written bare names the only output at the time it was written. Adding a second accumulator to a region with one, through `SetConfig`, or a second output to a function, leaves a bare link outside naming one of several outputs. The checker reports it at the link, so nothing passes silently, but E2's region and function editing should name the port first, as `name_bare_counter_links` does for variants.
- **Other float casts in WGSL.** G2's emitter should use the WGSL cast for these kinds and no hand clamp of its own, so the GPU and the definitions agree by construction. Any later kind that converts a float to an integer in a shader takes the same rule.
- **The hash core and library 1.** Library 1 must not freeze before the core is chosen.
